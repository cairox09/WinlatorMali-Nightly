# Winlator Mali Nightly

[![Sync Winlator Mali builds](https://github.com/cairox09/WinlatorMali-Nightly/actions/workflows/sync.yml/badge.svg)](https://github.com/cairox09/WinlatorMali-Nightly/actions/workflows/sync.yml)

Automated mirror of APKs generated by the GitHub Actions workflow from **[GunaCharanTeja/WinlatorMali](https://github.com/GunaCharanTeja/WinlatorMali)**.

The upstream project currently distributes development builds through **GitHub Actions artifacts** rather than regular GitHub Releases. This repository automatically finds the latest available Winlator Mali build artifacts, verifies them, extracts the APKs, and publishes them in a permanent rolling GitHub Release.

> [!IMPORTANT]
> This is an **unofficial mirror**.  
> The APKs are produced and signed by the upstream project.  
> This repository does **not** modify, rebuild, patch, or re-sign them.

## Download

Latest mirrored builds:

**[Download Winlator Mali Nightly Builds](https://github.com/cairox09/WinlatorMali-Nightly/releases/tag/nightly)**

Depending on what upstream has built, the Release may contain:

- `Winlator-Mali-Standard-Release.apk`
- `Winlator-Mali-Antutu-Release.apk`
- `Winlator-Mali-Ludashi-Release.apk`
- Debug variants such as `Winlator-Mali-Standard-Debug.apk`

Each APK also gets a matching `.sha256` checksum file.

## Variants

Winlator Mali currently defines multiple Android flavors:

| Variant | Android package | Description |
| --- | --- | --- |
| **Standard** | `com.winlator.mali` | Normal Winlator Mali package |
| **AnTuTu** | `com.antutu.ABenchMark` | Alternate package identity using the AnTuTu package |
| **Ludashi** | `com.ludashi.benchmark` | Alternate package identity using the Ludashi package |

Because these package names differ, Android treats the variants as separate applications.

## How the mirror works

The workflow in [`sync.yml`](.github/workflows/sync.yml) periodically checks the upstream repository for Winlator Mali APK artifacts.

For each available artifact channel, it:

1. Finds the newest non-expired artifact.
2. Verifies that it came from the expected upstream branch and workflow.
3. Downloads the original GitHub Actions artifact ZIP.
4. Verifies its SHA-256 digest against the value reported by GitHub Actions when available.
5. Extracts every APK contained in the artifact.
6. Keeps the APK unchanged.
7. Generates a SHA-256 checksum for each APK.
8. Publishes the APKs in the rolling `nightly` GitHub Release.

The workflow supports both single-APK artifacts and artifacts containing multiple flavors.

Synchronization runs automatically every hour at minute `:37`.

It can also be started manually from the **Actions** tab.
